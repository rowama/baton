# Worker research, 2026-11-06

Worker profile: `claude-code-research`.

## Inclusion criteria

- Creators: the frontier labs (Anthropic, OpenAI, Google, xAI, Meta), widely used alternatives (Mistral, DeepSeek, Qwen/Alibaba, Moonshot, Z.ai, Cohere), and open-weight releases from any of them (gpt-oss, Gemma, Qwen open weights, Whisper).
- A model is added only when an official creator page, or the hub/host page that serves it, names it on 2026-11-06. Third-party aggregators and search snippets were not used as sources for IDs.
- Per creator, the current flagship plus one cheaper or smaller tier and any open-weight or single-task model (transcription, OCR). Older still-available generations are left out unless they are the only pinned ID.
- Categories: models that do a bounded job on supplied input (LLM, vision-capable LLM, transcription of a file, document OCR). Live/realtime, TTS, image/video/music generation, embeddings and rerankers were excluded: either they are interactive sessions, or none of the capability vocabulary describes their output.
- A route is added only when the host page shows the exact identifier and the LiteLLM docs show the provider prefix (and key variable, for a new provider). If a page doesn't show an ID is pinned, or the ID is documented as re-pointed, the route is alias: true with no model_id.
- Capabilities come only from the capabilities input and need documented evidence, or the same maintainer judgment the seed used (long_form_writing / technical_reasoning for flagship-class models). structured_output and tool_use are claimed only where the source documents them. vision is claimed only where image input is documented.

## Coverage gaps

- Not exhaustive. About 16 provider/host sources were read for one day. OpenRouter's catalog could not be enumerated: /api/v1/models returned an odd 10-entry, Anthropic-shaped response, and /models showed about 20 entries. Only OpenRouter IDs confirmed on their own model pages were added.
- No route was live-checked, and nothing was recorded under `verified`. Also, the checker script for the proposed file couldn't run in this environment (the Python run was not approved). The file was hand-checked against the rules: lower-case `creator/name` ids, capabilities only from the input, every non-alias route's model_id defined, every alias route has a creator and no model_id. It is not machine-validated.
- OpenAI's models page doesn't say whether gpt-6-astra / gpt-6.1-sol / gpt-6-luna are pinned snapshots or moving aliases, so those routes are alias: true. If OpenAI documents them as pinned, they should get model_id routes.
- structured_output was not claimed for any new model. No source read this run confirmed JSON-schema-conforming output for OpenAI, Gemini, Mistral, DeepSeek, xAI or others. tool_use was claimed only for OpenAI (models page lists functions), gpt-oss and Gemma 4 (Ollama 'tools' badge), and Claude.
- Vision support is unconfirmed for xAI (the page doesn't say which models take images), Gemini 3.x Flash models (only Gemini 4 Argon's modalities were on the list page), DeepSeek V4 Pro (stated not supported), and Kimi K3.
- Transcription routes (groq/whisper-large-v3, gemini/gemini-3.5-transcribe) are marked supported: false. LiteLLM serves them through litellm.transcription(), and I could not confirm the litellm_api adapter makes that call. OCR has no route because Mistral OCR uses a separate endpoint.
- Local runtimes (Ollama, via LiteLLM's ollama_chat/ prefix) and Hugging Face routes were not added. The format's provider kinds seen are only direct_api, intermediary and harness, and a local runtime also brings in machine-dependent loopback networking. See the question for the owner.
- Providers with models recorded but no route: Alibaba DashScope (qwen3.8-max), Moonshot (kimi-k3), Z.ai (glm-5), Cohere (command-a-plus-05-2026, cohere-transcribe-03-2026), Meta Model API (muse-spark-1.3). LiteLLM lists dashscope/, moonshot/, cohere/ prefixes, but their key variables were not confirmed, and no LiteLLM prefix for Z.ai or Meta's Model API was confirmed.
- Not covered at all: Amazon Bedrock, Google Vertex AI, Azure/Microsoft Foundry, Together AI, Fireworks, Cerebras, other clouds; creators such as AI21, Microsoft Phi, NVIDIA Nemotron, MiniMax, Tencent, Liquid, IBM Granite, Reka; dedicated vision-only models (e.g. SAM 3.1) and OCR from other creators; Mistral Voxtral transcription (current API ids not shown on the overview).
- Claude Code harness routes for claude-fable-5-1 and claude-haiku-5-5 were not added, because the model-config page was not re-read this run. The older Claude generations that are still available (Opus 5, Opus 4.x, Sonnet 5, Sonnet 4.6, Haiku 4.5, Fable 5) were not added.
- DeepSeek's legacy names deepseek-chat / deepseek-reasoner were announced as discontinued on 2026-07-24. No later changelog entry confirms they are gone, so they were neither added nor marked retired (they were never in the file).
- Tier assignments for new entries are judgment from vendor positioning (flagship → strong, mid → standard, small/lite → basic), not from benchmarks.
